# Rift Lens

라이엇이 공개하지 않는 롤 솔로랭크의 **숨은 실력대(MMR)**를 추정해 보여주는 웹사이트.
→ https://rift-lens.xyz

최근 솔로랭크 경기에서 같은 로비에 배정된 플레이어들의 현재 랭크를 역추적해,
"실제로 어느 실력대와 매칭되고 있는지"를 계산합니다.

## 스택

- **Next.js 16** (App Router, React 19)
- **shadcn/ui**(base-ui) + Tailwind CSS v4 — 다크모드 지원
- **Recharts** — 실력대 추이 그래프
- **Postgres**(Supabase) — 분석 결과·매치·랭크 스냅샷을 관계형 테이블로 저장
- **satori**(next/og) — 결과 카드·OG 이미지 서버 생성

## 실행

```bash
npm install
cp .env.example .env.local   # 아래 환경변수 채우기
npm run dev
```

### 환경변수

| 키 | 필수 | 설명 |
|---|---|---|
| `RIOT_API_KEY` | ✅ | 라이엇 API 키 (https://developer.riotgames.com) |
| `RIOT_RATE_LIMITS` | | 키 한도 지정. `"용량:윈도초"` 콤마 구분 (예: `45:10`). 미설정 시 개발 키 프리셋(20/1s·100/2분) |
| `DATABASE_URL` | ✅ | Supabase Postgres. **트랜잭션 풀러(6543)** 사용 — 세션 모드(5432)는 동시 15클라이언트 제한 |
| `CRON_SECRET` | | 새벽 자동 갱신 크론(`/api/cron/refresh`) 인증용 |

> 개발용 키는 24시간마다 만료됩니다. Personal/Production 키는 영구이며,
> 한도가 다르므로 `RIOT_RATE_LIMITS`로 실제 한도(응답 헤더 `X-App-Rate-Limit`)를 지정하세요.

DB 스키마는 첫 요청 시 자동 생성됩니다(`src/lib/db.ts`). 별도 마이그레이션 불필요.

## 추정 방식 (ALGO_VERSION 4)

1. 최근 솔로랭크 경기를 조회해 **리메이크(5분 미만) 제외**
   - 같은 팀에 2회 이상 등장한 플레이어가 있는 경기는 **듀오로 간주해 분석 제외**
     (듀오 로비는 파트너 실력대에 오염됨 · 부족분은 과거 경기로 **백필**,
     그래도 4경기 미만이면 제외 포기)
   - 단 **듀오 금지 구간**(한국 마스터+ / 전 서버 그랜드마스터+)은 감지를 끔 —
     좁은 최상위 풀에서는 재등장이 자연스러워 오탐이 되기 때문
2. 경기마다 양 팀에서 3명씩 샘플링해 참가자들의 **현재 솔로랭크** 조회
3. 티어/디비전/LP를 단일 포인트로 환산 (아이언4 0LP = 0pt, 디비전당 100pt, 마스터+ = 2800pt + LP)
4. 로비별 **절사평균**(표본 5명 이상이면 최고/최저 제외)으로 부캐·복귀 유저 이상치 완화
5. 오래된 경기부터 순차 추정: 로비 평균으로 관측 보정(35%) → **Elo 승패 업데이트**(K=32).
   강한 로비를 이기면 크게 오르고, 예상된 승리는 조금만 오름
6. 로비 평균들의 표준오차로 **95% 오차범위(±pt)** 표기 + 표본 수 기준 신뢰도 표시

알고리즘을 변경할 때는 `ALGO_VERSION`을 올립니다 — 저장된 구버전 결과가 자동으로 재분석됩니다.

### 빠른 추정 / 정밀 분석

| | 경기 수 | 매치당 표본 |
|---|---|---|
| 빠른 추정 | 8 | 6명 (팀별 3) |
| 정밀 분석 | 20 | 6명 (팀별 3) |

첫 검색은 빠른 추정을 즉시 보여주고, 백그라운드에서 정밀 분석이 돌아갑니다.
진행률 배지가 표시되고 완료 시 페이지가 자동 갱신됩니다.

- **대기열**: 정밀 분석은 전역 락으로 한 번에 1건만 실행(레이트리밋 분산 방지).
  DB 대기열로 선착순 보장하고 배지에 순번을 표시합니다. 상위 5명은 화면을 나가도
  순번이 유지되고, 폴링이 곧 스케줄러라 어느 요청이든 대기열 헤드의 잡을 시작시킵니다.
- **우선순위 리미터**: 페이지 로딩(전경) 호출이 백그라운드 정밀 분석보다 항상 먼저
  슬롯을 받습니다 — 분석 중에도 검색이 굶지 않습니다.

### 캐시·신선도

- 분석 결과는 **30일 보관**하되 신선도 기준은 **72시간**
- 새 경기가 생기거나 72시간이 지나면: 저장된 결과를 **즉시 표시**하고
  ("이전 분석 표시 중" 배지) 백그라운드 재분석 후 자동 갱신 (stale-while-revalidate)
- 매치 상세는 불변이라 장기 보관, 참가자 랭크는 72시간 재사용 —
  같은 시간대 로비가 겹칠수록 API 호출이 크게 절약됩니다
- **재분석 버튼**: 매치 목록 캐시를 우회해 새 경기를 즉시 확인하고, 변화가 있을 때만
  재분석 (소환사당 60초 서버 쿨다운)
- 크롤러(OG 미리보기 봇·검색엔진)는 분석을 유발하거나 기록을 남기지 않습니다

## 주요 화면

| 경로 | 설명 |
|---|---|
| `/` | 검색 (자동완성) |
| `/summoner/[region]/[riotId]` | 분석 결과 — 실력대, 티어 갭, 로비 분포, 추이 차트, 전적 |
| `/recent` | 최근 검색된 소환사 목록 |
| `/team` `/duo` `/recap` | 내전 팀 밸런서 · 듀오 궁합 · 시즌 결산 |
| `/faq` `/updates` | 자주 묻는 질문 · 업데이트 내역 |
| `/admin` | 관리자 — 실행 중 분석, 대기열, 소환사별 분석 상태, 점검 모드 |

## 배포

Vercel 서버리스 호환:

- 백그라운드 작업은 `after()`(next/server)로 실행 — 응답 후에도 계속 진행
- 잡 상태·대기열은 DB에 저장 — 인스턴스가 갈려도 진행 상황이 공유됨
- 폰트·엠블럼 파일은 `outputFileTracingIncludes`로 번들에 포함

> Riot Games와 무관한 비공식 팬 프로젝트입니다. 공식 API의 공개 데이터만 사용하며,
> 모든 수치는 통계적 추정치입니다.
